# I-ins 1.2.0 — шесть кабинетов страховой и юридической компании для macOS

Клиент, страховой агент, администратор, андеррайтер, юрист, актуарий.
FastAPI + SQLite + ML-модели + поиск по базе знаний. Работает на любом Mac
2020 года и новее — Apple Silicon и Intel — без пересборки под конкретную машину.

## Установка

```bash
git clone https://github.com/<владелец>/I-ins.git
cd I-ins
chmod +x I-ins.command
xattr -dr com.apple.quarantine .
./I-ins.command
```

Первый запуск занимает 10–20 минут: собирается комплект из `payload/`,
создаётся окружение Python, ставятся библиотеки и распаковывается 262 МБ
данных. Дальше запуск — секунды.

Пошагово, включая требования к Python, — в `ИНСТРУКЦИЯ_MACOS.md`.

Комплект лежит в репозитории **распакованным** (`payload/modules`) и оттуда же
работает: архив не собирается и вторая копия на диск не пишется. Самый крупный
файл — 36 МБ, поэтому Git LFS не нужен, обычный `git clone` работает.

## Куда всё ставится

Окружение Python и рабочие данные кладутся:

| Условие | Папка |
|---|---|
| задана переменная `IINS_HOME` | в неё |
| есть `~/goinfre` (учебные Mac) | `~/goinfre/I-ins` |
| иначе | `~/Library/Application Support/I-ins` |

На учебных машинах домашняя квота мала, а локальный диск смонтирован как
`~/goinfre` — установщик сам выбирает его и сообщает путь перед началом.
Учтите, что `goinfre` периодически очищается: после очистки достаточно снова
запустить `./I-ins.command`, комплект переустановится.

Поставить в другое место:

```bash
IINS_HOME=/Volumes/Data/I-ins ./I-ins.command
```

Нужно около 1,5 ГБ — почти всё это библиотеки Python. Сам комплект места не
занимает: он работает прямо из `payload/`.

## Выбор языковой модели

В каждом из шести кабинетов в строке ввода вопроса есть переключатель режима
ответа:

| Режим | Что делает | Что нужно |
|---|---|---|
| Авто | берёт Qwen RAG, если он запущен; иначе ответ по базе знаний | ничего |
| RAG по базе знаний | ответ собирается только из найденных фрагментов PDF | ничего |
| Qwen RAG (локально) | локальная модель Qwen через Ollama, контекст из базы знаний | Ollama на этом Mac |

В режиме Qwen RAG модель получает **только** те фрагменты,
которые вернул поиск по базе знаний. Если поиск ничего не нашёл, генерация не
запускается вовсе, и кабинет отвечает, что основания в базе нет.

### Локальный Qwen

Проще всего — запустить готовый скрипт: он найдёт Ollama, поднимет её,
выберет место под модель и скачает её, если нужно.

```bash
./QWEN_SETUP.command
```

Скрипт ничего не ставит молча: если Ollama на Mac нет, он скажет об этом
и покажет, как её поставить. Вручную то же самое:

```bash
brew install ollama
ollama serve &
ollama pull qwen2.5:1.5b
```

Кабинеты подхватывают Ollama сами, перезапуск не нужен. Точный тег значения
не имеет: если скачана другая версия Qwen — `qwen2.5:3b`, `qwen3:4b` и так
далее — кабинеты возьмут её и подпишут ответ именем той модели, которой он
получен.

Проверить, что видит программа:

```bash
ollama list                    # что скачано на этом Mac
./I-ins.command --check-only   # строка «Qwen RAG: …» скажет, готов ли он
```

Если Ollama слушает не на стандартном адресе:

```bash
OLLAMA_BASE_URL=http://127.0.0.1:11500 ./I-ins.command
```

## Отчёты кабинета актуария

Вкладка «Отчёты» строит аналитический документ в три шага, и в PDF эти шаги
разделены:

1. **Расчёт** — показатели считаются по данным кабинета: моменты и квантили
   премии, асимметрия и эксцесс, критерии Шапиро — Уилка и Д'Агостино —
   Пирсона, структура портфеля по территориям и группам CGR, метрики обученной
   модели из отчёта обучения.
2. **Интерпретация** — языковая модель Qwen RAG получает только эти числа
   и объясняет их словами. Раздел подписан именем
   модели и режимом, которым он получен.
3. **PDF** — документ со сводкой, таблицами, интерпретацией и оговоркой о том,
   какая часть посчитана, а какая написана моделью.

Четыре вида отчёта: распределение премии с проверкой нормальности, портфель
премий, качество тарифной модели, тарифные факторы. Готовые PDF остаются в
папке данных и доступны из той же вкладки.

Модель не имеет доступа ни к чему, кроме вычисленных чисел, и не пересчитывает
их: разделять посчитанное и объяснённое — сознательное решение, а не
ограничение.

## Проверка

```bash
./I-ins.command --check-only     # окружение, модели, база знаний
./I-ins.command --smoke-test     # поднимает все шесть кабинетов и проверяет их
```

Smoke-тест проверяет вход, главную страницу, полноту базы знаний, ответ поиска,
наличие всех режимов ответа и то, что готовая языковая модель действительно
отвечает. Отчёт: `logs/smoke-test.json` в папке данных.

## Изменения в 1.2.0

- Во всех шести кабинетах есть выбор режима ответа: по базе знаний или Qwen RAG.
- Исправлены кабинеты клиента и администратора: на FastAPI 0.141 и новее они
  отвечали ошибкой 500 на каждый запрос — счётчики Prometheus обращались к
  атрибуту, которого у новых объектов маршрутизации нет. Разбор маршрута
  заменён на устойчивый, метрики продолжают работать.
- Комплект хранится и работает распакованным, без Git LFS и без сборки архива.
- На учебных Mac установка идёт в `~/goinfre`, где есть место.
- В кабинете актуария появились аналитические отчёты: расчёт, интерпретация
  языковой моделью и выгрузка в PDF.
- Smoke-тест проверяет наличие всех режимов ответа и работу языковой модели
  во всех шести кабинетах.
